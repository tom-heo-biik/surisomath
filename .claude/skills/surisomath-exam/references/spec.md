# 시험대비 규격


## 쪽
단위: 한 쪽에 문제 둘(`<section class="exam">`). 두 단, 단마다 문제 하나
본문 영역: 475×682pt(31칸). 위에 머리줄, 44pt부터 바닥까지 두 단
학생 쪽: 문제 열 개면 다섯 쪽, 스무 개면 열 쪽. 문제 수가 홀수면 마지막 쪽의 오른 단이 빈다
선생님 쪽: 학생 쪽 뒤에 같은 짝으로(스무 개면 11~20쪽). 양식은 같고 이름 칸만 없다
표지, 제목 줄, 이름 칸 행: 없음
쪽번호: a4 그대로(- n -). 선생님 쪽까지 이어 센다
바깥 세로선, 가로선: 없음. 학교 시험지 꼴이다. 연마의 세 줄 상자는 쓰지 않는다


## 쪽의 세로 짜임
기준: 본문 영역 위 끝 = 0
0~11pt: 빈 반 칸
11~33pt: 머리줄. typo-0, neutral-1000. 본문 위상(11 + 22k)
33~44pt: 빈 반 칸
44~66pt: 문제 번호. typo-4. 제목 위상(22k)
66~77pt: 번호 아래 반 칸
77pt~: 지문 → 조건 상자 → 뒷문장 → 그림 → 표 → 보기 상자 → 소문항 → 선지. 블록 사이와 선지 아래 한 칸씩. 본문 위상
그 아래~682pt: 풀 자리. 빈 종이. 소제목, 심볼, 가로선 없음
반 칸을 두 번 비우는 까닭: 연마와 같다. 11 + 22 + 11 + 22 + 11 = 77


## 머리줄과 이름 칸
머리줄: 시험대비, 학년도와 학기와 시험(2026학년도 2학기 중간고사), 학년(중3), 단원(삼각비) 넷을 가운뎃점으로 잇는다
머리줄 서체: typo-0, neutral-1000
이름 칸: 첫 쪽만 머리줄 오른쪽 끝에 "이름"과 90pt 빈 자리(아래 선 0.4pt)
머리줄이 이름 칸과 겹치면: build.py가 경고한다


## 단
왼 단: x = 0~237pt
오른 단: x = 237~475pt
가운데 세로선: x = 237pt(쪽 기준 297pt). 번호 줄 위(44pt)부터 바닥(682pt)까지. neutral-1000, 0.4pt
세로선 좌표: 정수라야 화면에서 검게 보인다. 반반(237.5)이면 픽셀 경계에 걸쳐 회색이다
글 자리: 선에서 8pt
글 너비: 왼 단 229pt, 오른 단 230pt. build.py는 좁은 쪽 229pt로 잰다
단 넘침: WeasyPrint는 넘친 내용을 흘리지 않고 쪽을 쪼갠다. build.py가 풀 자리 상자의 쪽으로 밀린 문제를 짚는다("문제 블록이 단을 넘쳐 다음 쪽으로 밀렸다", "풀이 글이 단 바닥을 넘어 다음 쪽으로 이어진다")


## 풀 자리
산식: 문제 글부터 바닥까지 27.5칸에서 문제 블록의 칸 수를 뺀 것. 늘 .5로 끝난다
최소: 8칸. build.py가 가장 좁은 단의 칸 수를 알려 주고 8칸 아래인 단은 단마다 경고한다
줄이는 법: 글을 줄이지 않고 그림을 한 칸 줄인다. 표가 있는 문제는 그림을 3~5칸으로
꾸밈: 없음. 소제목, 심볼, 가로선, 답 칸, 배점 모두 없다


## 문제 번호와 지문
번호: 001부터 problems.yaml 차례대로. typo-4, 단 왼끝. 순서는 바꾸지 않는다
지문: typo-1, 한 문단. problems.md 문장 그대로, 표기만 조판
그림: 지문 아래 단 가운데. a4의 `.figure` 블록. 너비 229pt 안. 높이가 22의 배수가 아니면 멈춘다
units: yaml에 적지 않는다. SVG 높이가 칸 수다
그림 칸 수: 5~7. 도형 하나 5, 세로로 긴 그림 7, 좌표평면 6~7, 표가 있는 문제 3~5


## 선지 열
마크업: `<ol class="n7">`(① ② ③ ④ ⑤)
마커 칸: 14.8pt. ①(10.8pt) 뒤 4pt에서 글이 시작한다. exam.css의 ol.n7 --pad, build.py의 MARK_W. a4의 22pt가 아니다
항목 너비: 마커 14.8pt + 글 너비. build.py가 선지마다 잰다
5열: 다섯 모두 45.8pt(단 글 너비 ÷ 5) 안. 한 줄
3열: 다섯 모두 76.3pt(÷ 3) 안. ①②③ / ④⑤, ④는 ① 아래
1열: 그 밖. 다섯 줄. 항목 하나가 단을 넘으면 경고
여백(GUTTER): 6pt. 여러 열일 때 항목 너비에 더해 잰다
여백의 까닭: 칸에 딱 맞으면 다음 마커와 붙어 보인다. 근호 폭을 줄이자 0.3pt 차로 3열에 든 선지가 "2√6 ③"처럼 붙었다
두 칸 항목: 잉크 높이 16pt를 넘는 수식(분수)이 든 선지가 두 줄 이상 쌓이면 항목마다 두 칸(44pt, 글줄은 위 칸)
2열: 두 칸 항목이 둘씩 114.5pt(÷ 2) 안이면 ①② / ③④ / ⑤
한 줄에 다 드는 5열: 두 칸을 주지 않고 한 칸 그대로
관례: 수능과 모의고사


## 보기 상자
yaml: notes(목록, ㄱ부터)
자리: 그림 뒤, 선지 앞
마크업: `<div class="notes">`. 첫 줄 "보기"(12pt/500), 그 아래 `<ol class="bogi">`(ㄱ. ㄴ. ㄷ.)
마커 칸: 22pt
글: 안쪽 8pt
높이: (1 + 항목 줄 수)칸. 아래 한 칸
정본: 이차함수 012


## 조건 상자
yaml: conditions(목록, (가)부터), after(상자 뒤 문단, "f(4)의 값을 구하시오.")
정형구: "이차함수 f(x)가 다음 조건을 만족시킨다." 뒤에 상자가 온다
자리: 지문 바로 뒤, 그림 앞
마크업: `<div class="notes cond">`. 머리글 없이 `<ol class="cond">`((가) (나))
마커 칸: 33pt
높이: 항목 줄 수 칸. 아래 한 칸
정본: 이차함수 001
누가 정하나: 선생님. 조건이 둘이라고 상자가 아니다


## 상자 테두리
구현: 0.4pt를 `::before`가 상자 가장자리에 걸쳐 그린다
까닭: 상자 자체에 border를 주면 글줄이 0.4pt 내려가 그리드 검사(허용 0.25pt)를 벗어난다


## 삼각비의 표
yaml: table(head 머리 행, rows 몸 행 목록)
칸의 따옴표: 작은따옴표. `'$2^{\circ}$'`처럼 중괄호가 든 값은 흐름 목록 `[…]` 안에서 따옴표가 없으면 YAML이 깨진다
자리: 그림 뒤, 보기 상자 앞
마크업: `<table class="stat">`. 수행평가 통계 표와 같은 격자(교과서의 삼각비의 표가 격자다)
글: typo-0, 가운데
행: 22pt
선: 0.4pt neutral-500. 세로선까지
열: 같은 너비
높이: 행 수 칸. 아래 한 칸
값: 책 숫자 그대로(0.06, 0.99)
정본: 삼각비 001, 009, 010


## 소문항
yaml: subs(목록, (1)부터)
자리: 표 뒤, 선지 앞
마크업: `<ol class="n5 sub">`(a4 괄호형)
마커 칸: 33pt
높이: 한 항목이 한 칸. 단 너비를 넘으면 경고
정답: `(1) $\sqrt{5}-1$ (2) … (3) …`처럼 한 줄에
정본: 삼각비 011


## 정답 줄
자리: 선생님 쪽 풀 자리 첫 줄
꼴: `정답: ④`
서체: typo-0, neutral-500, 왼끝
길이: 한 줄, 단 글 너비 안. 넘으면 경고
객관식: 번호만(④)
서술형: 값만. `$18$`, `$-1$`, `$-2$, $3$`(둘이면 쉼표), `$(-2,\,4)$`, `$\left(-\dfrac{1}{2},\,\dfrac{9}{2}\right)$`(분수 좌표는 큰 괄호)
단위: 수식 뒤에 글자로. `$6\sqrt{3}$cm`, 182.35m, 2% 감소
큰 괄호: 10pt 회색 정답 줄에서 `\left( \right)`도 한 줄에 든다
소문항: `(1) … (2) … (3) …` 한 줄
answer: 필수. 선생님 쪽은 늘 붙고 단마다 정답 줄이 있다


## 풀이 글
yaml: `solution: |` 블록. 선택
자리: 정답 줄 다음 줄부터
줄: 줄마다 한 칸. 빈 줄은 한 칸을 비운다
서체: typo-1. 수식은 `$…$`
줄 너비: 단 글 너비(한글 19자쯤). 넘는 줄만 어절에서 가른다(build.py의 width_of). 단 바닥을 넘으면 경고
분수 분자의 근호: 글줄 상자 위로 3pt쯤 넘는다. 잇단 두 줄에서 세로로 겹치면 단마다 경고
없으면: 정답 줄만 찍히고 아래가 빈다


## 폴더와 파일 이름
단원 폴더: build/시험대비/{시험}/{학년}/{단원}/
시험 폴더: `YYYY` + `N학기` + `중간|기말`(20262학기중간). build.py가 정규식으로 읽는다
머리줄의 시험: 2026학년도 2학기 중간고사
파일 이름: 수리소_시험대비_2026_2학기중간_중3_삼각비. 학년과 단원은 폴더 이름 그대로
사진: {학습지 이름}_001.jpg …(수리소_시험대비_2026_2학기중간_중3_이차함수_001.jpg). photos.py가 git mv로 바꾼다
축소본: 긴 변 1400px. 임시 폴더
빌드 결과: 수리소_시험대비_….html, .pdf
PDF 날짜: 학기 첫날로 고정(1학기 3. 1., 2학기 9. 1.). 같은 입력이면 PDF도 바이트 단위로 같다. 폴더 꼴이 안 맞으면 yaml의 date
figures/: 그림 p*.svg. 수식은 m 지문, k 조건, e 뒷문장, b 보기, c 선지, a 정답, s 풀이, t 표 칸, q 소문항. 빌드마다 다시 그리고 안 쓴 것은 지운다
--png: 쪽 p01.png …(110dpi), 그림 있는 문제의 단 크롭 f001.png …(200dpi)


## 파일
templates/exam.css: base.css 위에 얹는 시험대비 스타일. 두 단, 머리줄, 이름 칸, 선지 열, 보기 상자, 조건 상자의 구현
templates/build.py: problems.yaml 하나로 그림 → 수식 → HTML → PDF → 검사. 연마 build.py를 모듈로 읽어 rich()를 쓴다. `--png {폴더}`로 쪽과 그림 크롭 PNG
templates/photos.py: 단원 폴더의 문제 사진을 {학습지 이름}_001.jpg …로 바꾸고(git mv) 긴 변 1400px 축소본을 임시 폴더에 뽑는다. 이미 양식 이름인 사진은 건드리지 않는다
templates/sample/: 견본 세 문제(객관식 5열, 그림 있는 서술형, 객관식 3열, 홀수 짝). 새 단원은 이 폴더의 problems.yaml과 figures.py를 복사해 출발한다
견본 회귀: build.py, exam.css, render.py, grind_figure.py를 고친 뒤 견본을 다시 빌드해 종료 코드 0이고 `git status --short .claude/skills/surisomath-exam/templates/sample/`이 비어 있으면 양식이 그대로다
grind_figure.py를 고쳤으면: 연마 견본, 연마 2026.09.12, 삼각비, 원과직선, 이차함수, 수행평가 여섯을 다 돌려 오탐이 없는지 본다


## yaml 필드
필수: text, answer
블록 차례: text → conditions → after → figure → table → notes → subs → choices
choices: 다섯, 목록. 있으면 객관식
conditions: 목록, (가)부터
after: 상자 뒤 문단
notes: 목록, ㄱ부터
table: head, rows
subs: 목록, (1)부터
figure: figures/ 안의 SVG 이름. figures.py의 저장 이름과 같아야 한다
alt: 그림 설명. PDF에는 안 찍힌다
solution: `|` 블록
적지 않는 것: exam, grade, unit, file, date(폴더 이름에서 만든다). units
번호: `"no": "004"`. 키와 값 모두 따옴표
따옴표: text에 `": "`가 들어가면 감싼다. 역슬래시는 따옴표 없는 글에서 그대로 살아 있다


## 문제에 넣지 않는 것
답 칸, 배점: 없음
딱지, 출처: [서술형], [도전 문제], [대표문제], [2016년 3월 교육청] 같은 것. 문제 글에 없는 것은 넣지 않는다


## 빌드 옵션
--png {폴더}: 쪽 PNG와 그림 크롭
--no-figures: 그림은 그대로 두고 글만
--no-check: 그리드 검사 건너뜀
표기 검사: 문제마다 munhang/templates/notation.py의 check(). `!`는 NAME_WARNINGS에 더한다
봉인 대조: 단원 폴더에 sealed.json이 있으면 munhang/templates/seal.py로 글과 봉인된 풀이를 대조. 바뀌었으면 `!`로 멈춘다
