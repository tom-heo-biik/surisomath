# 독립 검토자 브리핑 틀

Agent(general-purpose)에게 주는 글. <…>를 단원에 맞게 채운다. 검토자는 파일을 고치지 않는다.
검토 전에 사진 축소본(긴 변 1100px, PIL로)과 크롭 PNG(build.py --png)를 스크래치 폴더에 뽑아 둔다.
결과는 사람이 가른다 — 받아들인 것과 안 받아들인 것을 problems.md 머리에 적는다(surisomath-munhang SKILL.md '검토').

---

당신은 수리소 수학학원 '<양식>' 학습지(<학년> <단원>, <N> 문제)의 독립 검토자다. 어떤 파일도 고치지 말고(Edit/Write 금지, git 명령 금지) 읽고 풀고 보고만 하라. 콘솔이 cp949라 파이썬은 `PYTHONIOENCODING=utf-8 python …`으로 돌려라. 저장소는 C:/허문영/surisomath 이다.

자료
- 원문 사진 축소본(문제 하나가 한 장, 번호가 문제 번호): <스크래치>/photos/<단원>/001.jpg … — Read 도구로 본다(한 번에 서너 장씩).
- 퇴고한 지문: <단원 폴더>/problems.md (머리에 무엇을 어떻게 바꿨는지 기록이 있다)
- 빌드 입력: <단원 폴더>/problems.yaml (지문·선지·정답. 수식은 TeX)
- 조판 결과 크롭(문제 글 + 그림 + 선지): <스크래치>/<단원>_png/f001.png … 쪽 전체는 p01.png …(앞 절반 학생, 뒤 절반 선생님 정답).

맥락(집의 규칙 — .claude/skills/surisomath-munhang/SKILL.md)
- 지문은 평가원(수능·모의평가) 문형으로 퇴고했다. 수식·수치·조건·답은 바꾸지 않고 문형만 다듬는 것이 원칙이다.
- 표기: 길이·크기라는 수는 식 안에서 기호($\overline{\mathrm{AD}}=6$, $\angle\mathrm{B}=90^{\circ}$), 도형 그 자체는 낱말(선분 AC, 각 C). 한 문제에 둘이 같이 있는 것은 뜻이 달라서 허용된다. 어긋남은 (가) 기호가 식 밖에 홀로("$\overline{\mathrm{AC}}$는"), (나) 낱말 뒤에 = : < ⊥("선분 AB = 6"). 각의 크기 문자는 θ°(둘이면 θ₁°·θ₂°). "그림과 같이 …인" 절에는 그림에 보이는 것만.
- 오늘 바꾼 것: <문제 번호와 무엇을. 특히 뜻이 걸린 것은 스스로 따져 보라고 적는다>

할 일 — 문제마다 네 가지를 보고, 문제가 있는 것만 보고한다
1. 사진 대조: 사진의 문제와 problems.md·yaml의 지문·선지·정답(표·소문항)을 견줘 수식·수치·조건·선지 차례·선지 값이 다른 곳. 문형(말투)이 다른 것은 의도한 것이니 보고하지 않는다. 다만 뜻이 달라진 곳(조건이 약해지거나 세지거나, 물음이 바뀐 곳)은 보고한다.
2. 문형 검토: 평가원 출제위원의 눈으로 지문을 읽고 어색한 문장, 모호한 곳, 그림과 안 맞는 서술, 빠지거나 넘치는 조건, 오탈자를 잡아라. 잡은 것마다 고친 문장을 통째로 제안하라(낱말 하나만 던지지 말 것).
3. 크롭 검토: f0NN.png를 보고 수식이 깨지거나 줄 바꿈이 이상한 곳, 그림의 점 이름과 지문의 점 이름이 안 맞는 곳, 그림의 점 자리가 사진과 다른 곳, 각·길이 표시가 지문과 다른 곳.
4. 독립 풀이: 문제를 스스로 풀어 yaml의 answer와 견줘라. 계산은 sympy로 되짚어라(스크립트를 <스크래치>/review_<단원>.py에 써서 돌려도 된다). 답이 다르면 풀이를 적어라.
(둘째 검토라면 1번 앞에 "표기 규칙 대조"를 둔다 — (가)(나)와 같은 뜻 다른 꼴.)

보고 형식(한국어, 간결하게)
- 맨 위에 한 줄 총평: 정답 대조 n/N 일치, 사진 대조 불일치 n건, 문형 지적 n건, 크롭 지적 n건.
- 그 아래 문제 번호 순으로 지적만 나열. 항목마다 [사진]/[문형]/[크롭]/[정답]/[표기] 꼬리표, 근거, 제안 문장.
- 지적이 없는 문제는 적지 않는다. 마지막에 "지적 없음: 001, 003, …" 한 줄.
- 확신이 낮은 지적은 "(확신 낮음)"을 붙여라. 근거 없는 취향 지적은 하지 말라.
